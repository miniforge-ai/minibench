# feat: commit the example correction so CI exercises the corrected-diff path

## Overview

Ships one human-recorded correction under `fixtures/corrections/`, written
by `minibench correct`, so `bb regression-gate` takes its corrections-aware
branch on every run. Also reconciles the two PR docs that described this
fixture's status, one of which described it wrongly.

## Motivation

`bb regression-gate` guards its `--corrections` flag on
`(fs/exists? "fixtures/corrections")`. The directory never existed —
`git log --all -- fixtures/corrections` is empty — so the guard never
fired and the flag was never passed. `diff_with_corrections`, the whole
point of PR #17, was covered by kernel unit tests and by nothing else. No
CI run has ever loaded a correction file off disk, parsed it through
`load_corrections`, or printed a corrected report.

PR #17 made that choice deliberately: "a committed correction is a
recorded human judgment with attribution; none ships until a human has
actually made one." The reasoning holds. What was missing was the human
judgment, not the wiring. This PR supplies it rather than working around
it.

## Changes in Detail

- **fixture** (`fixtures/corrections/career.lens.acme-l4-eval__haiku-mechanical__career.lens.report_grounded.json`):
  one `CorrectionV1`, generated by `cargo run -p minibench-cli -- correct`
  (not hand-written), accepting a **0.40 grounding floor** for
  `career.lens.report_grounded` on the `haiku+mechanical` variant of
  `career.lens.acme-l4-eval`. This is the example PR #17's doc and
  `correction_against_committed_baseline_changes_the_diff_outcome` both
  describe; it now exists as a file instead of only in-test. Attributed to
  `christopher@miniforge.ai`, pinned to snapshot
  `wb-haiku+mechanical-20260720T065605Z`.
- **docs** (`2026-07-19-feat-correction-loop.md`): amendment recording
  that "`fixtures/corrections/` ships empty" was not achievable — git does
  not track empty directories — and that the withholding rule has now been
  satisfied rather than reversed.
- **docs** (`2026-07-20-feat-gate-all-fixture-sets.md`): its gap note
  claimed PR #17's doc "describes a committed example correction". It does
  not; it states the opposite. Corrected in place, with the actual
  mechanism (the guard never firing) stated, plus an amendment pointing
  here.

No code changes. The CLI, the kernel, and `bb.edn` are untouched — the
wiring was already correct and already tested. Only its input was absent.

## What the gate now does

Before: `fs/exists?` false → `diff fixtures/baseline fixtures/experiments`.
After: `fs/exists?` true → `diff … --corrections fixtures/corrections`,
which loads and validates the set, applies it, and prints the provenance
line.

```
corrected expectation applied: career.lens.acme-l4-eval [haiku+mechanical] career.lens.report_grounded
no regressions vs baseline
```

## The gate's floor for this one cell moves, deliberately

The committed baseline reads `fail 0.43`. The correction sets the enforced
floor to `0.40`. That is a real, intended loosening for this cell and no
other: a future run at 0.41 now passes where it previously failed. That IS
the correction loop — accepting a change with recorded provenance instead
of replacing the baseline wholesale. The floor still bites below 0.40.

Both directions were verified against a scratch copy of the experiments
directory rather than asserted (see Testing Plan).
